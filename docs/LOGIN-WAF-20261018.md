# Password login WAF rollout

Target approved by user: 3 password login requests per IP per fixed 600-second
window. WAF counters are regional, not an exact global quota. Shared Wi-Fi shares
the IP bucket. Keep the current Blob limiter until real WAF enforcement has passed.

`POST /api/login` is the only password verification route in this change.
`GET /api/auth` keeps session checks and `POST /api/auth` keeps logout. Legacy
`action=login` on auth returns 410; it must not bypass the dedicated WAF rule.
The rule covers optional .js and trailing-slash spellings; actual deployed route
normalization and bypass cases still require a live preview test. No rule covers
public reports, QR reading, Notes/workspace shares, or the separate Koofr project.
The browser handles non-JSON WAF 429 responses as a useful retry message.

## Stages

1. Stage the observation rule (30 requests/600 seconds, action log). It does not
   block requests. Deploy the login code to preview only and retain Blob limiting.
2. Publish observation only after reviewing the complete firewall diff. Observe
   actual traffic in Vercel. Check that login routes match; session/logout/share
   routes do not. A local mock counter is not proof of WAF behavior.
3. Change the single rate-limit rule to 3/600 with 429 enforcement in preview
   only. Publish, then test attempts 1–3 and rejection of attempt 4 with synthetic
   wrong passwords. Verify HTML/non-JSON error UX, URL aliases and cookies. Do not
   disclose real passwords or create a bypass header for testing.
4. After preview passes, review/publish enforcement for production and deploy
   the login code together. Confirm production counters and scope. Keep the old
   Blob limiter during this observation period; its 5/IP and 30/global per 15 min
   limits can temporarily be stricter across overlapping windows.
5. Removing the Blob limiter is a separate reviewed change after edge enforcement
   is verified. Reverting must not re-open password verification outside the WAF.

Do not publish unfinished backup/NAS code or change report sources as part of this
rollout. Do not count logout, session GETs or sharing visits as login attempts.
